# Project Context

> Verified against source code on 2026-10-02. Update this file when the stack or scope changes.

## Project Name

Form Platform (npm package name: `formapp`). PRD title: *Custom Form Builder & Calculation Platform*.
PRD source of truth: `form-builder-calculation-platform-prd.md` (2286 lines, Indonesian).

## Project Purpose

A web application where an authenticated form owner builds forms from a canonical JSON schema,
previews them through one shared renderer, publishes them, and collects responses — with a native
formula/calculation engine producing **server-authoritative** computed values (client values are UX
only, never trusted; see PRD §79 and §78).

## Business Goal

From PRD §4: create/edit forms, drag & drop fields, validation, calculations, conditional logic,
scoring, realtime preview, publish, accept and store submissions, manage responses, export responses.
Secondary (PRD §4.2): autosave, undo/redo, versioning, templates, audit log, responsive builder,
accessibility, secure formula parser, dependency graph, calculation optimization.

Explicitly out of MVP scope (PRD §5): realtime collaboration, custom domains, payment gateway,
workflow automation, webhooks, public API, marketplace, advanced analytics, multi-tenant RBAC.
**This matches the current codebase: there is no payment or email subsystem.**

### Authentication

Auth.js v5 in `src/lib/auth.ts`, re-exported through `src/auth.ts`.

- Credentials provider only (email + password), bcrypt compare against `User.passwordHash`
- `session.strategy: "jwt"` — the `sub` claim carries `user.id`
- `jwt` callback copies `user.id -> token.sub`; `session` callback copies `token.sub -> session.user.id`
- Session type augmentation in `src/types/next-auth.d.ts` (`session.user.id: string`)
- Route handlers: `src/app/api/auth/[...nextauth]/route.ts` (`GET`/`POST` from `handlers`)
- Custom pages: `pages: { signIn: "/login" }`
- No OAuth providers, no PrismaAdapter, no database sessions, **no email verification, no password reset flow** (tables exist only)

### Authorization

- No `middleware.ts`. Authorization is enforced per request in the server layer only.
- `src/server/services/auth-service.ts` exposes `getCurrentUser()` and `requireUser()`
  (`requireUser()` calls `redirect("/login")` when there is no session)
- `src/app/(app)/layout.tsx` calls `requireUser()`, so every route inside the `(app)` group
  (`/dashboard`, `/forms*`, `/responses`) requires a session
- Ownership is enforced in SQL, not by role checks: every `form-service` read/write filters
  `{ id: formId, ownerId }`. `Role` enum (`USER`, `ADMIN`) exists in the schema but **is never read**
  anywhere in `src/`
- Effectively 2 roles: unauthenticated visitor, form owner. `ADMIN` is unused so far.

### Payment

None. No payment provider, no checkout, no webhook, no order model. Explicitly a non-goal for the MVP.

### Email

None. No mailer, no templates, no email triggers. `VerificationToken` and `PasswordResetToken` models
exist in the schema but are unused by application code.

### External Services

None beyond the local PostgreSQL container. No third-party API clients, no analytics, no error tracker.

## Important Dependencies

- `@prisma/adapter-pg` + `pg`: Prisma 7 requires a driver adapter; `src/lib/db.ts` throws at import
  time if `DATABASE_URL` is missing, so any process touching the DB needs it
- Generated Prisma client is **not committed** (`/src/generated/prisma` in `.gitignore`).
  `npm run db:generate` is required after a fresh clone, before typecheck/tests/build can pass
- `@/` path alias configured only in `tsconfig.json` (and read by `vitest.config.mts`)

## Important Environment Variables

Defined in `.env` (gitignored) and documented in `.env.example`. Never commit real values.

```
DATABASE_URL=<required>          # postgresql connection string, e.g. postgresql://USER:PASS@localhost:5432/formplatform?schema=public
AUTH_SECRET=<required>           # Auth.js encryption secret; generate with: npx auth secret
AUTH_TRUST_HOST=<required>       # "true" for local/LAN access behind a proxy-less dev server
```

`prisma/seed.ts` additionally hardcodes local-only demo credentials for the seeded account; they are
development fixtures, not secrets, and are deliberately not copied into this documentation.

## Main Features

Implemented and verified in code:

- Register / login / logout (Credentials + JWT cookie)
- Authenticated app shell with navigation and sign-out
- Dashboard with 5 stat tiles and 5 most recent forms
- Form CRUD: create, rename/describe, duplicate, delete (with confirm step)
- Form list with status badges and response counters
- Form builder: add field by type, select field, edit label/field id/description/required/formula/options,
  move up/down, delete, save schema (creates a new immutable `FormVersion`)
- Canonical JSON form schema (`src/lib/form-schema/schema.ts`) with Zod validation, 18 field types
- Shared form renderer (`FormRenderer`) with modes `preview | public | edit-response`
- Field renderer for all 18 field types (`field-input.tsx`)
- Preview page `/forms/[formId]/preview` with desktop/tablet/mobile widths, reset, answered counter
- Shared validation engine (`src/lib/validation`) running on client and intended for server reuse
- Conditional visibility and conditional required rules
- Value coercion / normalization, per-type formatting (currency IDR/USD/EUR, percentage, dates)
- Section/block layout resolution (`buildFormBlocks`) for inline dividers and declared sections
- Audit log rows on create / edit / schema save / duplicate / delete
- Per-form `FormSettings` persisted from the schema on save
- Version history table: every schema save creates a new immutable version
- 49 unit tests (3 files) for schema, values/layout/format/parse, validation

Present in schema but not yet reachable from the UI:

- Response / ResponseAnswer / CalculationResult models (no submission flow exists)
- Form status transitions (`PUBLISHED`, `CLOSED`) — no publish action
- Public form route `/f/[slug]` — does not exist

Not started (see `AI_CONTEXT/TODO.md`): public form page, submission action, response
detail/editing/CSV, publish/unpublish, calculation engine (lexer/parser/AST/evaluator/functions/
dependency graph/circular dependency detection), formula builder UI + autocomplete, autosave,
undo/redo, templates, builder drag & drop, section editing UI, admin role usage, E2E tests.

## User Roles

| Role | Where defined | Permissions actually implemented |
|---|---|---|
| Visitor (unauthenticated) | no session | `/`, `/login`, `/register`. Everything under `(app)` redirects to `/login`. |
| Form Owner (`User.role = USER`, the only role in use) | `requireUser()` + `ownerId` filters | Own forms only: create, list, read, rename, delete, duplicate, build schema, view preview, view response pages. Can publish/manage responses only once those features exist. |
| System Admin (`User.role = ADMIN`) | enum only | **No code path grants admin anything.** Column exists, never queried. |
| Responder | PRD §6.3 | **Not implemented yet** — the public `/f/[slug]` form does not exist. |
